UNIT 1 — 10 HRS Cloud Computing Fundamentals
☁ What is Cloud Computing
Delivery of computing services (storage, servers, software, networking) over the internet — "the cloud". Provides on-demand access without managing physical infrastructure.
  • User-centric: Data belongs to you & shareable
  • Task-centric: Focus is on what needs to be done, not the app
  • Powerful: Thousands of computers working together
  • Intelligent: Data mining & analysis of pooled data
  • Programmable: Automated replication, redistribution, self-healing
📅 History of Cloud Computing
  • 1960s: J.C.R. Licklider coined the concept via ARPANet research
  • 1961: John McCarthy — computing can be sold like a utility (water/electricity)
  • 1999: Salesforce.com — first app delivery over the internet
  • 2002: Amazon Web Services launched (storage, compute, human intelligence)
  • 2006: Amazon EC2 — first true commercial cloud for everyone
  • 2008: Google Beta Search Engine; Microsoft Azure announced
  • 2009: Google Apps for enterprise cloud
  • 2012: Google Compute Engine released to public
  • 2013: Oracle Cloud launched (IaaS, PaaS, SaaS)
🔄 Evolution of Computing (5 Stages)
  • Mainframe Computing: Powerful central computer + dummy terminals. Used in banking, healthcare, govt, airlines
  • Personal Computing: Individual desktop/laptop for everyday tasks
  • Network Computing: LANs, WANs, internet — data sharing + remote access
  • Grid Computing: Distributed cross-org resources, large-scale tasks (scientific)
  • Cloud Computing: On-demand, pooled resources over the internet
🔲 Grid Computing
Combines computing resources from multiple locations for a common goal. Subset of distributed computing — like a virtual supercomputer across the internet.

3 Node Types:

  • Control Node: Server(s) that administrate the network & resource pool
  • Provider: Contributes unused resources to the pool
  • User: Consumes resources from the pool

Use Cases:

Genomic research, drug discovery, cancer research, weather forecasting, risk analysis, CAD, animation/VFX, collaborative projects

🌐 Distributed Computing
Network of independent computers (nodes) working together. Each node is self-sufficient but communicates via messaging.

Advantages:

  • Scalability: Add nodes as needed without major upgrades
  • Availability: Node failure doesn't stop the system; redundancy built in
  • Efficiency: Parallel processing, optimal resource utilization
  • Transparency: Appears as single entity to user; hides complexity

Architectures:

  • Client-Server: Clients request, servers provide
  • 3-Tier: Presentation → Application → Data layers
  • N-Tier: Extension of 3-tier with n layers for modularity
  • P2P: All nodes equal; each is both client & server (blockchain, torrents)

🌫 Fog Computing (Edge Computing)
Introduced by Cisco. Extends cloud computing to the edge of the network. Stores data & apps between cloud and end-devices.
  • Nodes = fog nodes (devices at the edge)
  • Reduces latency — processing done near where data is created
  • Improves real-time decision making
  • Reduces data sent to central cloud → saves costs

4 Types:

  • Device-level: Sensors, switches, routers
  • Edge-level: Servers/appliances at network edge
  • Gateway-level: Between edge and cloud
  • Cloud-level: Process before reaching end users
Uses: Connected cars, smart cities, Industrial IoT, connected health, AR/VR
📋 NIST Definition & 5 Characteristics
"A model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources that can be rapidly provisioned and released with minimal management effort."

5 Essential Characteristics:

  • On-Demand Self-Service — Provision without human interaction from provider
  • Broad Network Access — Available over network, any device
  • Resource Pooling — Multi-tenant, dynamically assigned
  • Rapid Elasticity — Scale up/down instantly to match demand
  • Measured Service — Pay-per-use metering

UNIT 2 — 10 HRS Virtualization & Cloud Architecture
🖥 Virtualization — Core Concept
Representation of physical computing resources in simulated (virtual) form through software. A software layer transforms physical hardware into virtual machines users can configure independently.
  • Software module = Hypervisor (VMM — Virtual Machine Monitor)
  • Virtual processor works only when physical processor backs it
  • Guest OS executes as if running directly on physical hardware
  • Running multiple VMs simultaneously on one physical machine

Benefits:

  • Resource efficiency: Max hardware utilization, no idle servers
  • Easier management: Software-defined policies, automated workflows
  • Minimal downtime: Failover between redundant VMs
  • Faster provisioning: Deploy VMs in minutes vs weeks for hardware

🗄 Server Virtualization
Creates and abstracts multiple virtual instances on a single physical server. A hypervisor is installed; multiple VMs each run their own OS.

Benefits:

  • Server consolidation: One physical = multiple logical servers
  • Simpler infrastructure: Fewer racks, cables, hardware
  • Cost reduction: Less power, cooling, hardware spend
  • Versatility: Each VM is independent with own OS
  • VM migration: Move VMs between hosts easily
Example: A 4-CPU 64GB RAM server can host up to 4 VMs each with 1 vCPU and 16GB RAM. Popular hypervisors: Microsoft Hyper-V, VMware vSphere.
📦 Application Virtualization
Separation of an app from the OS and hardware. App runs in an isolated sandbox/virtual bubble — cannot permanently modify host system files or registry.

3 Types:

  • Local App Virtualization: App runs on local CPU in a sandbox. Offline capable. Example: VMware ThinApp (.exe with no install)
  • Application Streaming: Only needed parts downloaded on-demand. Fast startup. Example: Citrix App Streaming, Adobe Creative Cloud
  • Server-Based: App runs on server; only UI streamed to user. Thin client. Example: Microsoft RemoteApp, Citrix Virtual Apps, Amazon AppStream 2.0

Key Benefits:

  • Zero-Conflict Isolation: Run two incompatible versions side-by-side
  • Security Sandboxing: Malware trapped in bubble, can't spread
  • Instant Updates: Update master file on server; all users auto-updated
Vendors: Microsoft App-V, Citrix Virtual Apps, Parallels RAS, VMware ThinApp/App Volumes
🌐 Network Virtualization
Converting network resources from hardware to software. Can combine multiple physical networks into one virtual network OR divide one physical into multiple virtual ones.

Two Approaches:

  • SDN (Software-Defined Networking): Separates control plane from data plane. Control plane = central controller; data plane = forwarding. Can prioritize traffic (e.g., video calls over app traffic).
  • NFV (Network Function Virtualization): Replaces hardware appliances (routers, firewalls) with VMs on commodity servers. NFV provides infrastructure for SDN.

Traditional vs SDN:

  • Traditional: control plane + data plane are embedded together
  • SDN: control plane is separated as a central controller for many data planes
Examples: VLAN, Google Cloud/AWS virtual networks, Netflix streaming, Telecom providers (AT&T, Verizon, Jio) using SDN+NFV
💾 Storage Virtualization
Pooling physical storage from multiple devices into a single logical storage unit managed by a central console.

2 Types:

  • Block-Level Virtualization: Works at smallest storage unit (blocks). Used in SANs. Key component = LUN (Logical Unit Number). Uses RAID for redundancy + performance.
  • File-Level Virtualization: Works at file system layer. Multiple file servers appear as one. Used in NAS. Uses DFS (Distributed File System), NFS, SMB protocols. Example: Google Drive

RAID = Redundant Array of Independent Disks

Combines multiple HDDs into a logical unit for redundancy + performance. Protects against data loss if a drive fails.

🏛 Storage Network Architecture — 3 Layers
  • Host Layer (Servers): Servers/hosts that generate or consume data. Run applications. Rely on fabric layer to access storage. Can be virtualized.
  • Fabric Layer (Network Infrastructure): Switches, routers, cables connecting servers to storage. Protocols: Fibre Channel (FC), iSCSI, FCoE. Enables load balancing, redundancy, fault tolerance.
  • Storage Layer: Actual storage devices — disk arrays, SSDs, object storage. Implements RAID, data deduplication, compression. Centralized data pool for all servers.

📡 Web 1.0, 2.0, and 3.0
  • Web 1.0 (1991–2004) "Read-Only": Static pages, CDN-based content delivery, server-side file systems, CGI/SSI, frames & tables. Few creators, many consumers. Example: Yahoo! Directory, Netscape, MSN
  • Web 2.0 (2004–now) "Read & Write": User-generated content, dynamic content (AJAX), social interaction, APIs, participative. AJAX = Asynchronous JS+XML for background server calls. Example: Facebook, Twitter, YouTube, Wikipedia, Amazon, eBay
  • Web 3.0 (2020s+) "Read, Write & Execute": Blockchain-based decentralization, AI/ML, Semantic Web (machines understand data), cryptocurrency, smart contracts. Example: Bitcoin, Ethereum, DApps, AI assistants, DAOs
Key Web 2.0 features: Free sorting of info, dynamic content, site owner ↔ user flow, developed APIs, broader user base
💻 Web Operating System (WebOS)
An internet-based user interface that allows accessing applications not stored locally but on the internet. A dummy OS that doesn't interact directly with hardware; relies on traditional OS. Interface for distributed/cloud computing.
  • Apps, hard disk, OS all reside on remote servers
  • GUI feels like a PC desktop environment
  • Portable — access from any browser, any device
  • No hardware problems; just need browser + internet

Features:

Calendar, calculator, text editor, audio-video player, photo editor, email client, IM, file storage, file sharing, desktop search, mini-browser, games

Disadvantages:

  • Dependent on network speed and server load
  • Authentication, access control, privacy issues
  • Requires fast, reliable internet connection
🔐 Cloud Security — Overview
Set of policies, technologies, controls designed to protect cloud environments from threats. Ensures CIA triad: Confidentiality, Integrity, Availability.

Key Aspects:

  • Data Security: Encryption, access controls, secure backups
  • IAM: Only authorized users/devices access resources
  • Network Security: Firewalls, IDS, secure configurations
  • Threat Detection: Malware, ransomware, DDoS detection
  • Compliance: GDPR, HIPAA, ISO 27001
  • Incident Response: Breach response + data recovery
  • Secure APIs: Protect from SQL injection, unauthorized access
Traditional security used perimeter-based firewalls. Cloud breaks this — resources are outside the network boundary, requiring a new de-perimeterized security philosophy.
⚠ 8 Main Cloud Security Threats
1. Misconfiguration
Improper cloud configs — default creds, open S3 buckets, excessive permissions, open ports, unpatched systems. Impact: data breaches, DoS, financial loss.
2. Insecure APIs
Weak auth, no encryption, excessive data exposure. Example: Capital One breach 2019 — 106M customers' data stolen via misconfigured API.
3. Account Hijacking
Weak passwords, reuse, phishing. Example: Uber 2022 — attacker stole creds via phishing, bypassed MFA via repeated push notifications.
4. External Data Sharing
Cloud makes sharing easy (links, email). Hard to control access to shared resources. Anyone with URL can access.
5. Malicious Insiders
Already has authorized access. Harder to detect in cloud since org lacks control over underlying infrastructure.
6. Unauthorized Access
Cloud infra directly accessible from internet (no perimeter). Misconfigured security or compromised credentials = direct attacker access.
7. Cyberattacks
Malware, ransomware, etc. targeting cloud systems and data.
8. DoS/DDoS Attacks
Flood servers with traffic to make services unavailable. Exploit networking protocol vulnerabilities.
+ Vendor Lock-In: Over-dependency on one CSP due to proprietary tech, high migration costs, contractual constraints. Example: Netflix deeply tied to AWS. Prevention: multi-cloud, Docker/Kubernetes/Terraform (open standards), monitor exit costs.
🛡 Cloud Attack Prevention Tips
  • Enhance security policies — Define scope of responsibility clearly
  • Strong authentication — MFA: OTP + biometrics + hardware tokens
  • Implement access management — Role-based permissions (RBAC)
  • Protect data — Encrypt at source, in transit, at rest. Use tokenization.
  • Detect intrusions — Managed IDS (AWS GuardDuty, Azure Defender, Snort)
  • Secure APIs — OAuth 2.0, JWT, TLS, rate limiting, PoLP
  • Protect cloud services — Minimize event handler permissions
Tokenization: Replacing sensitive data (credit card: 4111 1111 1111 1111) with token (TKN_89FJ-82KS-KJ29-QW88)
🔒 Cloud Security Measures
  • Encryption: Data encrypted in transit and at rest
  • Access Control: IAM — only authorized users access data
  • Network Security: Firewalls, VPNs, network monitoring
  • Physical Security: Biometric auth, surveillance cameras at data centers
  • Compliance: ISO 27001, SOC 2, PCI DSS certifications
  • Disaster Recovery: Robust DR and business continuity plans
  • Monitoring & Auditing: Detect/respond to incidents, maintain activity logs
🏛 Cloud Security Working Groups
CSA (Cloud Security Alliance): World's leading non-profit for cloud security best practices. Based in Washington, US. Offers CCSK certification (Certificate of Cloud Security Knowledge).

CSA Objectives:

  • Common understanding between cloud providers and consumers on security
  • Develop best practices via independent research
  • Educational programs (CCSK certification)
  • Standardized list of cloud threats
Jericho Forum: Formed 2004, proposed Cloud Cube Model in 2009 (accepted as global standard). Became part of 'The Open Group' and closed in 2013 (objectives fulfilled). Members: IBM, Symantec, Boeing, AstraZeneca, HP, etc.
🧊 Cloud Cube Model (Jericho Forum, 2009)

Designed to address the de-perimeterization problem. Helps categorize and select cloud formations using 4 dimensional security criteria.

📍
Data Boundary
Internal vs External
Where is data physically stored? Inside org campus (private cloud) vs outside (public cloud)
🔑
Ownership
Proprietary vs Open
Proprietary = trade secret tech (limited interop). Open = follows published open standards.
🔐
Security Boundary
Perimeterized vs De-perimeterized
Perimeterized = inside org network (VPN for external). De-perimeterized = open collaboration, data-level encryption.
🏢
Sourcing
Insourced vs Outsourced
Insourced = own team manages (→ private cloud). Outsourced = 3rd party delivers (→ can be public or private).
📑 Elements of Cloud Security Model
  • Privileged user access: Ask provider who manages the cloud
  • Regulatory compliance: Choose providers with security certifications & external audits
  • Data location: Know where data is stored (consumers usually don't)
  • Data segregation: Separate different consumer data with encryption
  • Recovery: Provider must declare recovery process and timeline
  • Investigative support: Contractual commitment for investigation support
  • Long-term viability: What happens to data if provider shuts down?
⚖ Load Balancing
Distributes network traffic equally across a pool of resources. Ensures no server is overloaded/underloaded/idle. A load balancer sits between user and server group.

How it works:

  • Client request → Load balancer receives it
  • Algorithm routes to best-suited server in farm
  • Server responds → load balancer forwards to client
  • Load balancer handles SSL offload (decrypt TLS so servers don't have to)
Static Load BalancingDynamic Load Balancing
RulesFixed, independent of server stateExamines current server state
TrafficDivided equallyRoutes to lightest/least busy server
Best forLow-variation load systemsReal-time, varying load
DecisionPre-set, no real-time commsReal-time communication needed

Load Balancing Advantages:

  • Availability: Detects server failure, redirects to working servers
  • Scalability: Direct traffic intelligently across servers
  • Security: Built-in DDoS protection layer
  • Performance: Better response time, reduced latency
👤 Identity Access Management (IAM)
Manages users and permissions for cloud resources. Defines roles, access privileges, and conditions for granting them. One digital identity per individual — maintained throughout access lifecycle.

4 Components:

  • Authentication: Username/password, digital signatures, digital certificates, biometrics
  • Authorization: Access control — which user can access which resource
  • User Management: Create users, manage groups, password policies, privileges
  • Credential Management: Establish identities and access control rules
Without IAM: multiple accounts each with own billing, OR shared single credentials with no access control. IAM solves both problems under one account.

UNIT 4 — 10 HRS Cloud Providers & Case Studies
☁ Amazon EC2 (Elastic Compute Cloud)
Part of AWS — provides scalable virtual computing environments (instances) in the cloud. Launched 2006. Users can launch, configure, and manage VMs on demand.

Key Features:

  • Elastic: Scale compute capacity up/down in minutes
  • Instance types: General purpose, compute-optimized, memory-optimized, GPU, storage-optimized
  • AMI (Amazon Machine Image): Pre-configured OS + software template to launch instances
  • Pricing models: On-demand, Reserved, Spot, Dedicated Hosts
  • Security Groups: Virtual firewall controlling inbound/outbound traffic
  • Elastic IP: Static public IP address for dynamic cloud computing
  • Auto Scaling: Automatically adjusts capacity based on defined conditions
  • Load Balancer (ELB): Distributes traffic across EC2 instances
Other core AWS services: S3 (object storage), RDS (relational DB), Lambda (serverless), VPC (virtual private cloud), CloudWatch (monitoring), IAM, DynamoDB, CloudFront (CDN)
📄 Amazon Web Services — SLA & Recent Developments
AWS SLA (Service Level Agreement) guarantees uptime and performance commitments. AWS EC2 SLA guarantees 99.99% monthly uptime for multi-AZ (Availability Zone) deployments.

SLA Key Points:

  • If uptime drops below 99.99% → service credits issued
  • Below 99.0% → 30% credit; 99.0–99.99% → 10% credit
  • Availability Zones = isolated data centers within a region for redundancy
  • Regions = geographic areas with multiple AZs

Recent Developments:

  • AWS Graviton4 chips: Custom ARM-based processors for better performance + energy efficiency
  • Inferentia2: Custom ML inference chip; faster AI workloads
  • Amazon Bedrock: Managed service for foundation models (GenAI)
  • AWS Outposts: Bring AWS infrastructure on-premises
  • Sustainability: 100% renewable energy achieved 7 years early; infrastructure 4.1x more efficient than traditional data centers
🔷 GoGrid
An early cloud computing provider offering IaaS. Founded 2008. Allowed users to deploy and manage cloud servers, load balancers, and storage. Merged into Datapipe, later acquired by Rackspace.
  • Offered both Windows and Linux cloud servers
  • Pay-per-use pricing model (hourly billing)
  • Web-based control panel for infrastructure management
  • One of the first competitors to Amazon EC2
  • Provided persistent storage (Cloud Storage)
  • Supported load balancing out of the box
  • Notable for: multi-OS support, hybrid cloud capability
💼 Salesforce.com
Pioneer of SaaS — launched 1999. World's leading CRM (Customer Relationship Management) cloud platform. Delivered enterprise software over the internet, proving the cloud model works.

Key Products:

  • Sales Cloud: CRM for sales teams — leads, opportunities, contacts
  • Service Cloud: Customer service and support management
  • Marketing Cloud: Email marketing, digital advertising, analytics
  • Commerce Cloud: E-commerce solutions
  • Tableau: Data analytics and visualization
  • Einstein AI: AI-powered predictions and automation
  • MuleSoft: API and integration platform
  • Slack: Business collaboration (acquired 2021)
Significance: First to prove enterprise software could be delivered as a subscription service over the internet, pioneering the SaaS model.
🔧 Force.com (Salesforce Platform)

  • Allows developers to build custom apps that integrate with Salesforce CRM

🟢 Google App Engine
Google's PaaS offering. Allows developers to build and deploy scalable web applications on Google's infrastructure without managing servers. Fully managed serverless environment.

Key Features:

  • Standard Environment: Fully managed, auto-scaling, sandboxed. Free tier available.
  • Flexible Environment: Docker containers on GCP VMs. More control.

🇮🇳 Government of India Cloud (GI Cloud / MeghRaj)

Eucalyptus Components:

  • CLC (Cloud Controller): Main entry point; manages the whole cloud, handles requests
  • Walrus: S3-compatible object storage service
  • CC (Cluster Controller): Manages node controllers in a cluster
  • NC (Node Controller): Runs on each physical machine; manages VM instances
  • SC (Storage Controller): Manages block storage (EBS-compatible)
Use case: An organization wants AWS-like cloud internally without paying AWS. Eucalyptus lets them build it on their own servers, compatible with AWS tools.

⚡ Trick Questions / Confusables
  • IaaS = lowest level; SaaS = highest level in SPI stack
  • HaaS ≠ IaaS — HaaS is physical hardware rental; IaaS includes virtualization layer
  • Grid computing ≠ Cluster computing — grid is hetero, geographically dispersed; cluster is homo, local LAN
  • Fog computing = Edge computing (both terms used for same concept)
  • Hypervisor = VMM = Virtual Machine Monitor
  • NFV provides infrastructure for SDN (not the other way around)
  • Jericho Forum → became The Open Group → closed 2013
  • Cloud Cube Model = 4 dimensions (not 3, not 6)
  • GI Cloud = MeghRaj = managed by NIC (not ISRO, not MeitY directly)
  • Eucalyptus = AWS-compatible (EC2 + S3 API compatible) private cloud
  • Walrus in Eucalyptus = S3-compatible object storage
  • CLC = Cloud Controller (main entry point of Eucalyptus)
  • NIST has 5 characteristics + 3 service models + 4 deployment models
  • Web 1.0 era: 1991–2004
  • Static load balancing = no real-time comms; Dynamic = real-time comms needed
